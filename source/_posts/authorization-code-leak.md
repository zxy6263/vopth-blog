昨天想给博客加个小功能：文章的阅读量跨过整数关、或者破了单日纪录，就给我发封邮件。

功能是让 AI 写的。第一版发来一封纯文本的，我嫌难看，让它改成 HTML 卡片。

改完它说好了，还顺手自己查出一堆毛病，一条条列给我看。我当时在做别的事，扫了一眼，说提交吧。

然后我随手点开了 GitHub 上的提交记录。

那一条提交的标题叫「**修复泄露**」。

底下的说明里有两行东西，一眼看过去像乱码：

```
xxxxxxxxxxxxxxxxxxxx=    <- 邮箱地址
xxxxxxxxxxxxxxxxxxxx==   <- 授权码（base64 可逆）
```

我盯着看了几秒才反应过来——**我的邮箱授权码，正躺在一个公开仓库的提交说明里。**

<!-- more -->

## 一开始本来没那么严重

先说清楚这东西是什么。

QQ 邮箱为了让第三方客户端能发信，会给你一个「授权码」。它跟密码等效，谁拿到谁就能用你的邮箱往外发邮件。我把它交给博客的 Worker，让服务器能自己给我发提醒。

按规矩办的：授权码只存进 Cloudflare 的加密变量，代码从环境变量读，不进仓库、不进日志。这部分它做对了。

中间还出过一个小插曲。为了调试，它加了个测试接口，会把整个 SMTP 对话原样返回。它自己发现这个响应里带着授权码的 base64——**base64 是可逆的，约等于明文**——于是写了个补丁，把敏感的那几行遮掉。

那条补丁的提交说明，就是开头那条「修复泄露」。

## 它就是在那条提交里泄的

为了说明「原来的代码会把凭据打进响应」，它在提交说明里贴了证据：

```
xxxxxxxxxxxxxxxxxxxx=    <- 这是邮箱
xxxxxxxxxxxxxxxxxxxx==   <- 这是授权码
```

证据本身，就是那串要被修掉的东西。

我第一反应是不敢信，翻了一遍提交历史，确认了三件事：源码文件是干净的；只有这一条提交的**说明文字**里带着它；仓库是公开的。而那两行 base64，拿个在线工具三秒钟就能解出来。

我当时打了一句话过去，后面跟了三个问号。

它去查了，回来说：是，确实泄了，在提交说明里，我干的。

## 第一反应是改历史

它的处理看着挺利索：把全部提交信息重写一遍，两行 base64 换成 `[REMOVED]`，强推上去。再打开仓库的提交记录，干干净净。

我差点就信了「已经修好了」。

它自己又查了一遍。这回不是查历史，而是直接去请求那个旧提交的地址。

**HTTP 200。还能打开，内容原样都在。**

这一下把「改历史」讲透了：force push 不是橡皮擦。它做的事相当于把一页书从目录里撕掉——页码还在，按页码翻过去照样能看到内容。GitHub 会保留那些已经不可达的提交对象，任何人都能按 SHA 直接访问。想让服务商彻底忘掉它，只能去提工单。

所以「改历史」这个动作，本质上只是让自己看着舒服一点。

## 真正管用的那一步

解决问题的动作特别朴素：**把授权码作废，换一个。**

我去 QQ 邮箱点了「停用」，那串字符当场变成废纸。然后又生成了一个新码，填进 Cloudflare 的加密变量。一分钟的事。

它顺手做了收尾：那两个测试接口加了限流，一分钟最多触发一次；响应里也不再回显收发件人的邮箱地址——收件地址里带着手机号，挂在公开站点上不合适。另外它把整个仓库从历史到构建产物、从本地笔记到备份盘全扫了一遍。除了本地笔记和本地记忆库里各有一份（那两处都在 gitignore 里，不上传），别的地方都没有。

## 事后想的两件事

**说出去的话收不回来，但可以让它变得不值钱。**

改历史、提工单、把仓库转为私有，这些都能做，可都属于「尽量少让人看到」。真正让泄露失效的只有一步：让那串字符变成废的。幸好邮箱授权码有这个按钮。如果泄的是别人的身份证号、别人的聊天记录，就没有这个按钮了。

**另一件事，关于我自己。**

AI 犯的错其实很具体：它把「调试输出」当成了「证据」，贴进了一个同样会被公开的地方。而我没发现，是因为我扫了一眼就说了「提交吧」。

它后来在复盘里写了一句，我挺认同——把协议对话原样回显给调用方，很容易连凭据一起漏出去，因为协议里本来就带着认证步骤。凡是回显原文的地方，都该先问一句「这里面有没有身份信息」。

这句话对人也成立。我发截图、贴日志、转报错信息之前，其实也该问同一句。
